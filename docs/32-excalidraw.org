*Keybinding Note:* This extension uses Emacs-style keybindings where Ctrl is used on all platforms (not Cmd on Mac), except where explicitly noted.

* 👀 Overview

Scimax has its own Excalidraw editor for =.excalidraw=, =.excalidraw.json= and
=.excalidraw.svg= files, built to tie drawings to your org notes: a shape can
link to a heading, clicking it opens the heading, and a linked shape shows the
heading's TODO state. Drawings are indexed with your notes, so they show up in
search, in a heading's back-links and in the link graph. See [[*Scimax's
Excalidraw Editor]].

** 👀 Prerequisites

Nothing to install for =.excalidraw=, =.excalidraw.json= and =.excalidraw.svg=.
For =.excalidraw.png= files, or if you prefer it (=scimax.excalidraw.editor=),
install the Excalidraw extension from the VS Code marketplace:

| Extension ID              | Name               |
|---------------------------+--------------------|
| pomdtr.excalidraw-editor  | Excalidraw Editor  |

You can install it via:
- Command Palette: =Extensions: Install Extensions= → search "Excalidraw"
- Or run: =code --install-extension pomdtr.excalidraw-editor=

* ✅ Supported File Formats

Excalidraw supports multiple file formats, all of which work with this integration:

| Extension           | Description                              | Hover Preview |
|---------------------+------------------------------------------+---------------|
| .excalidraw         | Native Excalidraw format (JSON)          | Via exports   |
| .excalidraw.json    | Explicit JSON format                     | Via exports   |
| .excalidraw.svg     | SVG with embedded Excalidraw scene data  | Yes           |
| .excalidraw.png     | PNG with embedded Excalidraw scene data  | Yes           |

*Recommendation:* Use =.excalidraw.svg= or =.excalidraw.png= for best experience:
- These formats show hover previews directly
- They embed the full Excalidraw scene data, so they remain fully editable
- They can be displayed in exports (HTML, LaTeX, Markdown)

* ⚠️ Scimax's Excalidraw Editor

Opening a drawing (from the Explorer, the Notebooks view, or a link in an org
file) opens it in the Scimax Excalidraw editor: the full Excalidraw canvas,
with three buttons at the top right:

| Button          | Key       | What it does                                                    |
|-----------------+-----------+-----------------------------------------------------------------|
| 🔗 Link to note | =C-c C-l= | Link the selected shapes to a heading, file or another notebook |
| ＋ Linked box   | =C-c C-b= | Add a box linked to a heading, in the middle of the view        |
| Status          |           | Show or hide the TODO state of linked headings                  |

The drawing is an ordinary file: edits mark it unsaved, =Cmd+S= saves it, and
=Cmd+Z= is Excalidraw's own undo. An =.excalidraw.svg= is saved as an SVG with
the scene embedded, so it is still an image for exports and GitHub. Editing the
same file elsewhere (a text editor, =git checkout=) updates the open drawing.

To use the Excalidraw extension instead, right-click the file and choose
*Open With...*, or set =scimax.excalidraw.editor= to =pomdtr= for links in
org files.

** ⚠️ Linking a shape to a note

Select one or more shapes and press *🔗 Link to note* (=C-c C-l=). A picker
lists every heading in the drawing's project, indented by level, with its
TODO keyword, outline path and file; type to filter. The list ends with:

- *Heading in another notebook...*: pick a project, then a heading; the link
  is an =nb:= link, so it works from any notebook
- *A file...*: link to any file, relative to the drawing
- *Type an org link...*: any org link (=file:=, =id:=, =cite:=, =doi:=, web)

The link is written to the heading's =ID= when it has one, else its
=CUSTOM_ID=, else its title. A heading with neither is given an =:ID:= first
(as org-id does), so the link keeps working when you rename or move the
heading. Turn that off with =scimax.excalidraw.linkWithId=.

*＋ Linked box* (=C-c C-b=) does the same for a new box labelled with the
heading's title. From an org file, *Scimax: Add Heading to Drawing*
([[cmd:scimax.excalidraw.addHeadingToDrawing]]) adds a box for the heading at
the cursor to the drawing in view, or to one you pick (or a new one).

** ⚠️ Following links

Click a shape's link icon (or the link in its tooltip) and the heading opens
beside the drawing. Links work with every org link type; =id:=, =nb:=,
=::*Heading= and =::#custom-id= links are resolved by Scimax directly, without
the operating-system round trip and "allow this URI?" prompt the Excalidraw
extension needs.

** ⚠️ Live status on linked shapes

A shape linked to a heading is outlined, and badged with the heading's TODO
keyword and priority: orange for an open TODO, green for a done one, red for a
link that no longer resolves (*⚠ broken link*). Rest the pointer on the shape
for its context: the headings above it, the heading, the first lines of its
entry and its file and line. The overlay is drawn over the canvas and is not
saved in the drawing.

The status updates whenever an org file is saved, so a drawing of a project
works as a status board: mark a task DONE and its box turns green. *Status*
turns the overlay off.

* 👀 Hover Preview

When you hover over an Excalidraw link, a tooltip appears showing:

1. *Drawing name* - The filename or link description
2. *Visual preview* - For all Excalidraw file types:
   - =.excalidraw.svg= and =.excalidraw.png= files show the image directly
   - =.excalidraw= and =.excalidraw.json= files show a generated SVG preview
3. *Element count* - Number of shapes in the drawing
4. *Links* - For =.excalidraw= files, each linked shape and the org link
   it follows (see [[*Linking Drawings to Your Notes]])
5. *File information* - Size and last modified date

The hover preview for =.excalidraw= files renders the drawing with:
- Rectangles, ellipses, and diamonds with their colors and fill styles
- Lines and arrows with their arrowheads, dashed and dotted strokes
- Text, including labels inside shapes and on arrows
- Freedraw paths and embedded images

For best results, the extension first looks for companion export files (same name
with =.svg= or =.png= extension). If none exist, it generates a preview from the
JSON data.

1. The file is automatically created with an empty drawing

For =.excalidraw.png= files, or with =scimax.excalidraw.editor= set to
=pomdtr=, if the Excalidraw extension is not installed:
1. The file opens as a text document (showing JSON)
2. A message suggests installing the Excalidraw extension

* ⚠️ Linking Drawings to Your Notes

Shapes in a drawing can link back into your org notebook: click a box in
the diagram and VS Code jumps to the heading, custom id, file or line it
stands for. This turns a figure into a map of your notes.

** ⚠️ How the links work

Excalidraw keeps one link per element. The Excalidraw editor opens
=http=, =https= and =mailto= links in the browser and relative file paths
in VS Code, but it cannot follow org links such as =notes.org::*Results=.
Scimax gives those links a URI that VS Code routes back to scimax:

#+BEGIN_EXAMPLE
vscode://jkitchin.scimax-vscode/org-link?link=file%3A..%2Fnotes.org%3A%3A*Results
vscode://jkitchin.scimax-vscode/org-link?from=/path/notes.org&link=*Results
#+END_EXAMPLE

Scimax follows the =link= parameter exactly as it would follow the same
link clicked in an org file, so every link type works: =file:= with
=::*heading=, =::#custom-id=, =::42= (line) or =::text= searches, =id:=,
=cite:=, =doi:=, =nb:=, =cmd:= and web links. A relative path is relative
to the =from= file when the URI has one, and otherwise to the drawing.

When an =.excalidraw.svg= is written (by =scimax excalidraw build= or
=render=, the Notebook Map, or the editor when it saves), each org link in
its SVG markup gets =from== set to the drawing itself, written with =~= for
your home folder. A shape clicked outside VS Code (the SVG opened in a
browser or Quick Look) then still resolves its relative links against the
drawing, not whichever file is active in VS Code. The scene stored inside
the SVG is not changed, so the editor keeps resolving against wherever the
drawing is now. A drawing made before this change picks up =from== the next
time it is saved, or with =scimax excalidraw render drawing.excalidraw.svg=.

The first time you click such a link, VS Code may ask whether to let
Scimax open the URI. Allow it once and choose to not be asked again.

** 👀 Adding a link by hand

In the Scimax editor, use *🔗 Link to note* instead (see [[*Linking a shape
to a note]]). For the Excalidraw extension:

1. Put the cursor on a heading in an org file.
2. Run =Scimax: Copy Heading Link for Excalidraw=
   (=scimax.excalidraw.copyOrgLink=). It copies a link to that heading: an
   =id:= link when the heading has an =ID= property, otherwise a
   =#custom-id= or =*Heading= link to the file.
3. In the Excalidraw editor, select a shape, press =Ctrl+K= (=Cmd+K= on
   macOS) and paste the link.

Clicking the link icon on the shape now opens the heading.

** ⚠️ Building linked drawings from a spec

=scimax excalidraw build= turns a short JSON spec into a drawing. Shapes
take a =label=, arrows connect shapes by id with =from= and =to=, and
=orgLink= adds a link into your notes:

#+BEGIN_SRC json
{"elements": [
  {"id": "data", "type": "rectangle", "x": 0, "y": 0, "label": "Raw data",
   "backgroundColor": "#a5d8ff", "orgLink": "file:../notes.org::#data"},
  {"id": "fit", "type": "ellipse", "x": 280, "y": 0, "label": "Model fit",
   "orgLink": "file:../notes.org::*Model fitting"},
  {"type": "arrow", "from": "data", "to": "fit", "label": "clean"}
]}
#+END_SRC

#+BEGIN_SRC sh
scimax excalidraw build spec.json -o diagrams/pipeline.excalidraw.svg
#+END_SRC

The output is an =.excalidraw.svg=: an image with the scene embedded, so
the Excalidraw editor opens and edits it, and it is still an image for
exports and GitHub. =build= reports any link whose file, heading or custom
id does not exist and exits with status 1. See [[file:30-cli.org::*Excalidraw][Excalidraw in the CLI reference]]
for =render=, =check=, =links= and =json=.

The SVG that =build= writes has clean shapes and system fonts. The
Excalidraw editor redraws it in its hand-drawn style the next time you
save it.

* ⚠️ Drawings in Search, Back-links and the Link Graph

The database indexes drawings along with your notes
(=scimax.db.indexDrawings=, on by default):

- *Search*: the text on a drawing's shapes is searchable; the SVG/JSON is not
  indexed.
- *Back-links*: a heading that a shape links to (by =ID=, =CUSTOM_ID= or
  title) lists the drawing among its references, with the shape's label.
- *Link graph*: a drawing is a node, with an edge to every file its shapes
  link to, =id:= links included.

Drawings are re-indexed when saved, like org files.

* ⚠️ Notebook Maps

*Scimax: Notebook Map (Excalidraw)* ([[cmd:scimax.notebook.map]]), also on a
notebook's right-click menu and its *Drawings* section in the Notebooks view,
draws the notebook as =diagrams/notebook-map.excalidraw.svg=:

- one column per org file, the master file first, headed by a box linked to
  the file
- a box per top-level heading, linked to it (done headings in green)
- a dashed arrow from a heading to every file or heading its section links to
  (=file:=, =::*Heading=, =::#custom-id= and =id:= links)

Up to 12 files and 15 headings per file are drawn. The map opens in the
editor, where its boxes open their headings and show their TODO state, and
you can rearrange it like any drawing. Running the command again asks before
replacing it.

* ⚠️ Interactive Figures in HTML Export

A bare link to a drawing (no description), such as
=[[file:diagrams/pipeline.excalidraw.svg]]=, is exported to HTML as an
inline SVG, so its links work in the browser:

| Link in the drawing             | Link in the HTML            |
|---------------------------------+-----------------------------|
| =file:../notes.org::*Results=   | =notes.html#org-results=    |
| =file:../notes.org::#data=      | =notes.html#data=           |
| =id:abc-123=                    | =#abc-123=                  |
| =doi:10.1021/x=                 | =https://doi.org/10.1021/x= |
| =https://...=                   | unchanged                   |
| =cite:=, =cmd:= and other links | removed (the shape stays)   |

Paths are rewritten relative to the exported file, so they work when the
HTML files sit next to their org files, as =scimax export= and publishing
write them. =.excalidraw= and =.excalidraw.json= links are rendered to SVG
the same way. A =#+CAPTION:= or =#+NAME:= above the link makes the
drawing a =<figure>=.

Scripts, event handlers and =javascript:= links in an SVG are removed
before it is inlined. A link with a description, a missing file, or a
drawing over 20 MB is exported as before (an image or a plain link).
Clipboard export does not inline drawings.

** 👀 Drawings in the org preview

The org preview (=[[cmd:scimax.org.preview.openToSide]]=) inlines drawings
the same way, so their shapes are clickable there too. Clicking a shape
linked to a heading opens the org file in the editor with the cursor on that
heading (matched by its exported id or =CUSTOM_ID=). Links to Markdown files
open the =.md= file. The drawing is not editable in the preview; open the
link in the org file to edit it on the canvas.

** ✅ Export for Sharing
CLOSED: [2026-01-18 Sun 09:56]

Excalidraw's =.excalidraw.svg= and =.excalidraw.png= formats are ideal because:
- They display correctly in web browsers and image viewers
- They can be embedded in HTML/PDF exports
- They retain full editability (scene data is embedded)

** ✅ Version Control
CLOSED: [2026-01-18 Sun 09:56]

All Excalidraw formats are text-based (JSON or JSON-embedded), making them
suitable for version control with git. The =.excalidraw.svg= format shows
meaningful diffs for the SVG portions.

* ✅ Troubleshooting
CLOSED: [2026-01-18 Sun 08:40]

** 👀 Drawing won't open in visual editor

- If VS Code asks which editor to use, pick *Scimax Excalidraw* (both it and
  the Excalidraw extension can open drawings); *Open With...* changes it later
- An =.excalidraw.svg= that is a plain SVG with no embedded scene cannot be
  edited; Scimax offers to open it as text instead of overwriting it
- For =.excalidraw.png=, ensure the Excalidraw extension is installed: =pomdtr.excalidraw-editor=
- Check that the file extension is correct (=.excalidraw=, =.excalidraw.json=,
  =.excalidraw.svg=, or =.excalidraw.png=)
- Try reloading VS Code window

** ✅ No hover preview appears

- All Excalidraw file types now show hover previews
- For =.excalidraw= files, a simplified SVG is generated from the JSON
- The file must exist on disk for preview to work
- Empty drawings show "Empty drawing" instead of a preview

** ✅ Link not recognized as Excalidraw
CLOSED: [2026-01-18 Sun 08:40]

Ensure the file extension is one of:
- =.excalidraw=
- =.excalidraw.json=
- =.excalidraw.svg=
- =.excalidraw.png=
