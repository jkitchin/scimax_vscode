* ✅ Markdown Compatibility
CLOSED: [2026-01-19 Mon 09:32]

Scimax VS Code provides first-class support for org-mode files, with substantial
structural editing and navigation support for Markdown documents as well. This
chapter documents which features work in Markdown files and how to use them.

** 👀 Design Philosophy

The extension treats Markdown as a first-class citizen for *structural editing
and navigation*. TODO keywords, priorities, SCHEDULED/DEADLINE lines and
hashtags work in Markdown headings with the same syntax as org (see
[[*Tasks, Planning and Hashtags in Markdown]]). Clocking and properties drawers
are org only.

| Category                | Markdown Support | Notes                              |
|-------------------------+------------------+------------------------------------|
| Structural editing      | Full             | Headings, subtrees, code blocks    |
| Navigation              | Full             | Jump, outline, breadcrumbs         |
| Speed commands          | Full             | Single-key commands at headings    |
| Code block execution    | Full             | Fenced blocks with Babel/Jupyter   |
| TODO states             | Full             | =## TODO Title= or =## [TODO] ...= |
| Priorities              | Full             | =## TODO [#A] Title=               |
| Scheduling/Deadlines    | Full             | Planning line under the heading    |
| Agenda                  | Full             | Database and current-file agendas  |
| Tags                    | Full             | =#tags= or =:a:b:= ending a heading |
| Hashtags                | Full             | Coloured, hover, click, completion |
| Clocking                | None             | Org-mode specific syntax           |
| Properties              | None             | Org-mode specific syntax           |

* ✅ Supported Features
CLOSED: [2026-01-19 Mon 09:33]

** ✅ Document Outline and Navigation
CLOSED: [2026-01-19 Mon 09:33]

Markdown files have full support for the VS Code outline view and breadcrumb
navigation.

*** ✅ Outline View
CLOSED: [2026-01-19 Mon 09:33]

The extension provides a =DocumentSymbolProvider= for Markdown that recognizes:

- Headings (lines starting with =#=)
- Fenced code blocks (=```language= or =~~~language=)
- YAML frontmatter title

Open the Outline view in the Explorer sidebar or press =Ctrl+Shift+O= to see the
document structure.

*** ✅ Breadcrumbs
CLOSED: [2026-01-19 Mon 09:33]

Breadcrumbs show the current heading hierarchy in the editor title bar. This
works automatically for Markdown files.

*** ✅ Jump to Heading
CLOSED: [2026-01-19 Mon 09:34]

Press =C-c C-j= to open a quick-pick menu of all headings in the current file.
Type to filter and press Enter to jump.  `Cmd-C/Shift-o' also works.

** ✅ Heading Navigation
CLOSED: [2026-01-19 Mon 09:35]

All heading navigation commands work in Markdown:

| Key       | Command                   | Description                      |
|-----------+---------------------------+----------------------------------|
| C-c C-n   | Next Heading              | Move to next heading (any level) |
| C-c C-p   | Previous Heading          | Move to previous heading         |
| C-c C-u   | Parent Heading            | Move to parent (higher level)    |
| C-c C-j   | Jump to Heading           | Quick-pick menu of all headings  |

Speed commands (when cursor is at column 0 of a heading line):

| Key | Action                               |
|-----+--------------------------------------|
| n   | Next heading (any level)             |
| p   | Previous heading (any level)         |
| f   | Next heading (same level - forward)  |
| b   | Previous heading (same level - back) |
| u   | Up to parent heading                 |
| j   | Jump to heading (opens menu)         |

** ✅ Heading Manipulation
CLOSED: [2026-01-19 Mon 09:35]

Change heading levels and move subtrees:

| Key         | Command           | Description                      |
|-------------+-------------------+----------------------------------|
| M-<left>    | Promote Heading   | Decrease level (## -> #)         |
| M-<right>   | Demote Heading    | Increase level (# -> ##)         |
| M-S-<left>  | Promote Subtree   | Promote heading and all children |
| M-S-<right> | Demote Subtree    | Demote heading and all children  |
| M-<up>      | Move Subtree Up   | Swap with previous sibling       |
| M-<down>    | Move Subtree Down | Swap with next sibling           |

*** ✅ Insert Headings

*** ✅ Yank Subtree Level Adjustment
CLOSED: [2026-01-19 Mon 09:35]

When yanking (pasting) a subtree, the extension automatically adjusts heading
levels to match the context:

<!-- Yank a subtree that was cut from a different level -->
<!-- Headings are automatically adjusted to match ## level -->
#+END_SRC

** ✅ Code Block Support
CLOSED: [2026-01-19 Mon 09:37]

Markdown fenced code blocks have full support for:

- Detection and navigation
- Execution via Babel/Jupyter
- Block manipulation (split, merge, clone)

*** ✅ Fenced Block Syntax
CLOSED: [2026-01-19 Mon 09:37]

Both backtick and tilde fences are supported:


~~~javascript
console.log("Hello from JS");
~~~
#+END_SRC

Supported languages include Python, JavaScript, TypeScript, Shell, and any

** Folding
CLOSED: [2026-01-19 Mon 09:40]

Markdown headings support folding via the standard VS Code folding mechanism:

- Press =Tab= on a heading to cycle fold state
- Press =Shift+Tab= anywhere for global fold cycling
- Use the fold icons in the gutter

Fenced code blocks and Pandoc fenced divs (=::: {.callout-note}= ... =:::=,
nested to any depth, and MyST =:::{note}= fences) fold as well.

** Markdown Preview

VS Code's Markdown preview (=Cmd+Shift+V=, =Cmd+K V= to the side) gets these
additions from Scimax:

- *MyST directives and roles* (Jupyter Book) render as callouts, figures and
  highlighted code instead of raw =:::{...}= text. See [[file:45-myst-preview.org][MyST Preview]].
- *Reveal Cursor in Markdown Preview* (~scimax.marp.revealInPreview~) scrolls
  the preview so the element on the cursor line is at its top, opening a
  preview to the side if none is showing. It relies on
  ~markdown.preview.scrollPreviewWithEditor~ (on by default).
- *Export to PDF*: the export button in the preview's title bar
  (~scimax.markdown.preview.exportPdf~, also in the Command Palette while the
  preview has focus) saves the previewed file as =name.pdf= next to it and
  opens it. It uses Pandoc and LaTeX, like *Markdown → PDF* (see
  [[file:25-commands.org::*Markdown File Export][Markdown File Export]]), so the PDF is typeset
  rather than a copy of the preview's look; unsaved changes are included. A Marp
  deck exports its slides with Marp instead, as =p= in the Marp export menu
  does. The other markdown export commands and the export menu also work from
  the preview.

Files with ~marp: true~ in their front matter are previewed as slides; see
[[file:44-marp.org][Marp Slides]].

* Quarto Documents

Quarto files (=.qmd=) are Pandoc Markdown with executable code chunks. Scimax
works alongside the official [[https://marketplace.visualstudio.com/items?itemName=quarto.quarto][Quarto extension]] (=quarto.quarto=), which gives
=.qmd= files their language (~quarto~). Each extension does its own part:

| Feature                                           | Provided by |
|---------------------------------------------------+-------------|
| Syntax highlighting, YAML header completion       | Quarto      |
| Outline view, cross-reference completion          | Quarto      |
| Render and preview (=Cmd+Shift+K=, =Cmd+Shift+V=) | Quarto      |
| Running chunks in a Jupyter session               | Quarto      |
| Heading navigation, promote/demote, move          | Scimax      |
| Subtree kill, copy, yank, refile                  | Scimax      |
| Speed commands at a heading                       | Scimax      |
| Folding cycles (=Tab=, =Shift+Tab=)               | Scimax      |
| Tables, citations, timestamps, jump               | Scimax      |
| Code block split, clone, move, navigation         | Scimax      |

Everything in [[*Supported Features][Supported Features]] above works the same way in a =.qmd=
file as in a =.md= file.

** Code chunks

Scimax recognizes Quarto's chunk fences (=```{python}=, =```{r, echo=FALSE}=)
as code blocks, along with plain fences, =```{.python}= display blocks and
=```{=html}= raw blocks. Blocks that scimax inserts in a =.qmd= file use the
chunk form, so Quarto executes them; splitting, cloning and merging keep it.

=C-c C-c= in a chunk runs it with Quarto's *Run Cell* (~quarto.runCurrentCell~)
rather than scimax's own execution, because chunk output belongs in the
rendered page, not in the source. Quarto's own keys stay in charge in =.qmd=
files: =Cmd+Enter= (run line or selection), =Shift+Enter= (run and advance) and
=Cmd+Shift+K= (preview). In a =.md= file those keys keep their scimax
meanings, and =Cmd+Shift+K= on a citation still deletes it there.

=Cmd+Shift+V= (=Ctrl+Shift+V=) in a =.qmd= file also runs Quarto's *Preview*
(~quarto.preview~), so the preview key matches org and Markdown files.

** Callouts and other divs

Fenced divs (callouts, =::: {.columns}=, panels, =::: {#fig-x}= figure divs)
fold from the opening =:::= to its matching close, including nested divs.

* ⚠️ Tasks, Planning and Hashtags in Markdown

Markdown headings can be org tasks. A heading may start with a TODO keyword
(bare, or in brackets as =[TODO]= so it renders visibly), then a priority
cookie; tags are =#tag= words or an org =:a:b:= group at the end of the
title. A planning line with SCHEDULED, DEADLINE and CLOSED timestamps may
follow the heading directly:

#+BEGIN_SRC markdown
## TODO [#A] Write the introduction #paper #writing
SCHEDULED: <2026-11-03 Tue> DEADLINE: <2026-11-07 Fri>

## [NEXT] Send the draft to coauthors

## DONE Collect the data
CLOSED: [2026-10-30 Fri 14:12]
#+END_SRC

** ⚠️ Highlighting

Task headings are coloured as in org: TODO keywords red, done keywords
green, and the priority, =:tags:= and the SCHEDULED / DEADLINE / CLOSED line
with its timestamps in the theme's org colours. They are semantic tokens
(=orgTodo=, =orgDone=, =orgPriority=, =orgTag=, =orgPlanning=,
=orgTimestamp=), so =editor.semanticTokenColorCustomizations= can change them.

** ⚠️ Keywords

The default keywords are =TODO NEXT WAIT WAITING HOLD SOMEDAY IN-PROGRESS=
(active) and =DONE CANCELLED CANCELED= (done). Declare others with a
=#+TODO:= line, inside an HTML comment so it does not render:

#+BEGIN_SRC markdown
<!-- #+TODO: TODO REVIEW | DONE REJECTED -->
#+END_SRC

Put the declaration somewhere other than the first line when the first line
is a heading.

** ⚠️ Commands

| Key        | Speed key | Action                                          |
|------------+-----------+-------------------------------------------------|
| =C-c C-t=  | =t=       | Cycle the heading's TODO keyword                |
| =C-c ,=    | =,=       | Set the priority                                |
| =C-c C-s=  | =s=       | Schedule the heading the cursor is under        |
| =C-c C-d=  | =d=       | Set a deadline on the heading the cursor is under |
| =C-c C-c=  |           | Toggle a checkbox; recount a =[n/m]= cookie     |
| =C-c a < a= |          | Agenda view for the current file                |
| =C-c a < t= |          | TODO list for the current file                  |

=C-c C-s= and =C-c C-d= work anywhere in a heading's section, as in org:
they open the calendar date picker, write the SCHEDULED / DEADLINE line under
the heading, and add =TODO= to a heading without a keyword, so the task shows
in the agenda. Above the first heading they insert =@scheduled(...)= /
=@due(...)= at the cursor, as before. Cycling a =[TODO]= heading writes the
keyword bare (=TODO=).

** ⚠️ Checkbox Statistics

A =[n/m]= or =[n%]= cookie on a heading counts the checkboxes in its section;
on a list item, its direct child checkboxes. Toggling a checkbox (=C-c C-c=
or a click) updates the cookies above it, and =C-c C-c= on a line with a
cookie recounts it. As in org, a heading's cookie also counts its direct
subheadings with TODO keywords when you change one with =C-c C-t=.

#+BEGIN_SRC markdown
## Checkboxes [2/3]
- [x] task 1
- [x] task 2
- [ ] task 3
#+END_SRC

** ⚠️ Agenda

Indexed Markdown files take part in the database agenda and TODO lists
(=C-c a=), with priority, tags and planning dates. The first database sync
after updating re-indexes Markdown files. The agenda view for the current
file (=C-c a < a=) works on a Markdown file; agendas limited to a project
read only its org files.

** ⚠️ Hashtags

=#tags= in Markdown are drawn in blue, hover and click like in org (see
[[file:18-database-search.org::*Hashtags in the Editor][Hashtags in the Editor]]),
and are indexed. A heading's own =#= marks are not hashtags, but =#tags= in its
title are.

* ✅ Tips for Markdown Users
CLOSED: [2026-01-19 Mon 09:40]

** ✅ Maximizing Compatibility
CLOSED: [2026-01-19 Mon 09:41]

To get the most out of Scimax VS Code with Markdown:

1. *Use speed commands* - Position cursor at column 0 of headings for rapid
   single-key operations

2. *Use fenced code blocks* - The extension fully supports =```language= blocks
   for execution and manipulation

3. *Use the outline view* - Provides visual navigation similar to org's sparse
   tree features

4. *Use jump commands* - =C-c C-j= for headings, =C-c C-v g= for code blocks

** ✅ When to Use Org-Mode Instead
CLOSED: [2026-01-19 Mon 09:41]

Consider using org-mode files when you need:

- Task management with TODO states and priorities
- Scheduling and deadlines with agenda integration
- Time tracking with clocking
- Inherited properties and tags
- Advanced export features

Org files can be exported to Markdown when sharing with others who don't use
org-mode.
