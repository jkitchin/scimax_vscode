* 👀 Project Management

Building on [[file:03.5-task-dependencies.org][task dependencies]], Scimax turns a set of org TODO tasks into
a small project-management view: a **task table**, a **project view** with a
graphical Gantt chart, a **dependency graph**, and a **people database** with assignee autocomplete.
Everything is driven off metadata you already put on headings —
=SCHEDULED=/=DEADLINE=, =EFFORT=, priority, =:DEPENDS:=, and =:ASSIGNEE:=.

** ✅ The data a task carries
CLOSED: [2026-07-02 Thu 08:07]

#+begin_src org
,* Project X
  :PROPERTIES:
  :ID: proj-x
  :ASSIGNEE: jrk          ← whole subtree assigned to jrk (inherited)
  :END:
,** TODO Run analysis
   SCHEDULED: <2026-07-01 Wed>
   :PROPERTIES:
   :ID: analysis
   :EFFORT: 2d
   :END:
,** NEXT Make figures                      :@ana:   ← @tag also assigns
   :PROPERTIES:
   :ID: figures
   :EFFORT: 4h
   :DEPENDS: id:analysis
   :END:
,** TODO [#A] Write paper
   DEADLINE: <2026-07-20 Mon>
   :PROPERTIES:
   :ID: paper
   :EFFORT: 1d
   :DEPENDS: id:analysis id:figures
   :END:
#+end_src

- =EFFORT= accepts =2d=, =4h=, =0:30=, =90m= (a day = 8 hours).
- =:ASSIGNEE:= holds one or more handles; it is *inherited* from ancestor
  subtrees, and =@name= tags count as assignees too.

** 👀 Task table

Insert a table with [[cmd:scimax.org.insertProjectTable]], or write the dynamic
block yourself and refresh it with =C-c C-c=:

#+begin_src org
,#+BEGIN: project-table :columns task,todo,priority,assignee,deadline,effort,blocked
,#+END:
#+end_src

Parameters:

| Param             | Meaning                                                                 |
|-------------------+-------------------------------------------------------------------------|
| =:columns=        | Any of task, todo, priority, assignee, scheduled, deadline, effort, blocked, deps |
| =:id=             | Scope to the subtree with this heading =:ID:= (whole file if omitted)   |
| =:maxlevel=       | Only include headings up to this level                                  |
| =:match=          | Only tasks with these tags, e.g. =+urgent=                              |
| =:groupby=        | =assignee= or =state= — adds a grouping column                          |
| =:include_non_todo= | =t= to include headings without a TODO keyword                       |
| =:scope=          | =file= (default), =project= (every org file under the project root), or =agenda= (every indexed file) |

The =blocked= column shows 🔒 when a dependency in the block's scope is not yet
done. Columns may also include =file=, the task's file relative to this one.

With =:scope project=, the table gathers tasks from every =.org= file under the
project root (the nearest folder above this file with =.git=, =.projectile= and
the like), read from disk, with this file's unsaved text. A =file= column is
added by default, dependencies between files count for =blocked=, and =:id= does
not apply:

#+begin_src org
,#+BEGIN: project-table :scope project :groupby assignee
,#+END:
#+end_src

** ⚠️ Project view

[[cmd:scimax.project.view]] (*Scimax: Project View (Gantt Chart)*) opens a panel
with every TODO task in the active file's project on a graphical Gantt chart.
The tasks come from all the =.org= files under the project root, read the same
way as the task table's =:scope project=, and the panel reloads whenever one of them is
saved.

Each row shows the task's state, priority, a 🔒 when it is blocked, its title
and its assignees, with a bar on the timeline coloured by status: green done,
red blocked, dark blue in progress (its =SCHEDULED= date has come), light blue
planned,
and a yellow diamond for a milestone. Priority =[#A]= bars are outlined. Arrows
run from each dependency to the task that waits for it, and a red line marks
today. =SCHEDULED= is a bar's start, else the end of its latest dependency,
else the deadline minus the effort, else the project's earliest start (or
today). =EFFORT= sets the length in working days of 8 hours; a task with
=SCHEDULED= and =DEADLINE= but no effort runs to the deadline, and a task with
only a =DEADLINE= is a milestone. Children of an =:ORDERED: t= parent follow one
another.

- *Double-click* a task (or select it and press =Enter=) to open it beside the
  chart. The arrow keys move the selection.
- *Right-click* a task for: Open Task, Cycle TODO State, Assign..., Set
  Priority..., Set Effort..., Schedule..., and Set Deadline.... Each runs the
  ordinary Scimax command on the task's heading (so repeaters, CLOSED
  timestamps and dependency blocking behave as usual), saves the file, and
  comes back to the chart.
- The toolbar filters by *Assignee* (or *Unassigned*), groups rows by assignee,
  file or parent heading, shows or hides *Done tasks*, zooms the timeline with
  =-= and =+=, and scrolls to *Today*.
- *Tags* opens a checklist of the project's tags. Check one or more to show only
  the tasks that have /any/ of them; *Clear* shows every task again. A task's
  tags include those it inherits from parent headings and from =#+FILETAGS=, so
  checking =:paper:= on a parent heading's tag shows all the tasks under it.
  =@name= tags are assignees and are left out of the list. The button shows the
  chosen tags, and the tag filter combines with the assignee filter. A task's
  tags appear in its tooltip.

*** ⚠️ Exporting the chart

The *Excel* and *PDF* buttons in the toolbar, the right-click menu on the chart,
and the commands [[cmd:scimax.project.exportExcel]] and
[[cmd:scimax.project.exportPdf]] save the chart as it is shown, with the current
assignee and tag filters and grouping:

- *Excel* (=.xlsx=): one sheet with the task table (task, file, state, priority,
  assignees, effort in hours, start and end as real dates, blocked) and a
  day-by-day timeline to its right, each task's days filled in its status
  colour, weekends shaded and today highlighted. The header rows and table
  columns are frozen, so the timeline scrolls under them.
- *PDF*: a one-page vector chart with the same bars, milestones, dependency
  lines, today line and a legend. The page grows to fit every row and day, and
  viewers and printers scale it to the paper. Text is set in Helvetica, so
  characters outside Latin-1 (emoji, CJK) print as =?=; blocked tasks are marked
  =[blocked]=.

** ✅ Dependency graph
CLOSED: [2026-07-02 Thu 08:07]

[[cmd:scimax.org.showTaskGraph]] opens an interactive graph (nodes = tasks,
arrows = "depends on"), colored by status:

- 🔵 ready · 🔴 blocked · 🟢 done · ⚪ unresolved id

It is seeded from the active file's tasks and expands over the dependency edges
to show the connected component. Click a node to jump to that task.

** ✅ People and assignments
CLOSED: [2026-07-11 Sat 09:05]

A *person* is any heading tagged =:person:=, with contact properties:

#+begin_src org
,* John Kitchin                              :person:
  :PROPERTIES:
  :ID: person-jrk
  :EMAIL: jkitchin@andrew.cmu.edu
  :NICK: jrk
  :ROLE: PI
  :END:
#+end_src

- **Assign**: [[cmd:scimax.org.assignTask]] (*Scimax: Assign Task to Person*) lists
  the indexed =:person:= headings, fuzzy-matches on handle/name/role/email as you
  type, and sets the current task's =:ASSIGNEE:= property to the picked handle(s).
  Run it from anywhere inside the entry; pick more than one for a shared task.
  Existing assignees are pre-selected, and clearing the selection unassigns.
- **Autocomplete**: while editing an =:ASSIGNEE:= value, completion suggests
  known people (name + email) and inserts their handle (=:NICK:=, or a slug of
  the name).
- **Hover**: hovering an assignee handle shows the person's name, email, and role.
- **Capture**: [[cmd:scimax.org.newPerson]] prompts for name/email/nick/role and
  appends a =:person:= heading to your people file
  (=scimax.org.peopleFile=, default ={scimax.directory}/people.org=).

Assignees feed the table's =assignee= column and grouping (=:groupby assignee=),
the project view's assignee filter and grouping, and the agenda's =@= filter.

** 👀 Notes and limitations

- Without =:scope=, the task table is computed from a *single file* (or a
  subtree via =:id=). Use =:scope project= to cover the whole project.
- "Blocked" and the chart's ordering resolve dependencies within the scope: a
  dependency on a task outside the project is not counted. The dependency graph
  and completion blocking ([[file:03.5-task-dependencies.org][Task Dependencies]]) still see every indexed file.
- A project is read from disk each time the view or block refreshes. Very large
  trees are capped at 2,000 org files, with a warning.
- The Mermaid =#+BEGIN: gantt= block and its *Insert Gantt Chart* command were
  removed in favour of the project view. Updating an old =gantt= block reports
  "Unknown dynamic block type"; delete it and use the project view instead.
