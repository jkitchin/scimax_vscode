* Crucible Knowledge Bases

[[https://github.com/jkitchin/crucible][Crucible]] keeps a knowledge base as an interlinked org-mode wiki: primary
sources (papers, notebooks, data) are distilled by an LLM into concept,
summary, comparison and method articles, and a database tracks the concepts,
sources, links and derivations between them. Scimax lets you browse and
search crucibles from VS Code, and shows the graph around the article you
are reading.

Scimax works through the crucible command-line tool, so install it first:

#+begin_src bash
pip install crucible-llm
#+end_src

Scimax uses the CLI's =--json= output, which needs a recent crucible. If
VS Code does not find =crucible= on its =PATH= (for example when it lives in
a virtual environment), set ~scimax.crucible.command~ to its full path.

** The Crucible Panel

The *Crucible* panel in the Scimax sidebar lists the crucibles in your
workspace (marked /workspace/ and expanded), then the others in the global
registry (=~/.crucible/registry.json=), which =crucible init= adds each new
crucible to. Under each crucible:

- *Concepts* lists the crucible's concepts with their article counts;
  expand one to see the articles on it.
- *Concept articles*, *Summaries*, *Comparisons* and *Methods* list the
  articles of each kind by title.

Click an article to open it. A crucible's row has buttons to search it, open
its index (=index.org=) and sync its database. The panel's title bar has
*Search All Crucibles* and *Refresh*.

** Searching

*Scimax: Search Crucible* ([[cmd:scimax.crucible.search]]) searches the
crucible of the file you are in, the only crucible in the workspace, or one
you pick. *Scimax: Search All Crucibles* ([[cmd:scimax.crucible.searchAll]])
searches every registered crucible, and labels each result with the crucible
it came from. Results show the article's title, kind and abstract; pick one
to open it.

~scimax.crucible.searchMode~ chooses the search: =auto= (the default) uses
hybrid search when the crucible has embeddings and keyword search otherwise,
=fts= is keyword search, =semantic= finds articles by meaning (it needs
=crucible embed= and ollama), and =hybrid= combines the two.
~scimax.crucible.searchLimit~ caps the number of results (20).

** The Graph Around an Article

In a crucible article, three commands show its neighbours in the knowledge
graph. Each lists articles to pick from and opens the one you choose:

| Command                           | Shows                                                         |
|-----------------------------------+---------------------------------------------------------------|
| [[cmd:scimax.crucible.backlinks]] | Articles that link to this one, with the text around the link |
| [[cmd:scimax.crucible.related]]   | Related articles, with why (shared concepts, sources, links)  |
| [[cmd:scimax.crucible.history]]   | The articles it was derived from, and those derived from it   |

They appear in the command palette only when the active file is in a
crucible.

** Citations

Crucible articles cite their sources with org-ref links (=citep:key=), and
the entries live in the crucible's =.crucible/references.bib=. Opening an
article loads that bibliography, so citation hovers, completion and
navigation work in it (see [[file:19-references.org][References]]).

** ⚠️ The Crucible Graph

*Scimax: Show Crucible Graph* ([[cmd:scimax.crucible.graph]], also the graph
button on a crucible's row in the panel) opens the crucible's knowledge
graph beside the editor, as an interactive SVG. It needs a crucible with
=crucible graph --json=.

The graph shows the whole crucible. Articles are circles coloured by kind
(concept, summary, comparison, method) and sized by their connections;
concept tags are grey squares, and sources (off by default) are yellow
squares. Lines are links between articles (with arrows), tags (dotted) and
derivations (orange). Opened from an article, the view centres on it and
highlights its neighbours, and it follows you as you open other articles of
the crucible.

Hover a node for its title, kind and number of connections, with its
neighbours highlighted. Click an article or source to open it; click a
concept tag to add it to the tag filter, showing only its articles. Drag the background to pan; zoom with the
scroll wheel, a trackpad pinch, the =+= and =-= buttons or keys (titles
appear as you zoom in) and drag a node to move it. The toolbar finds
a node by title, shows or hides concept tags, sources and all labels,
centres on the current article (=c=), fits the whole graph (=f=) and
reloads it. The graph reloads itself after each =crucible sync=.

The second toolbar row filters the graph down to the articles you want.
Type a query and press Enter to keep only the articles =crucible search=
finds for it (with ~scimax.crucible.searchMode~); add concept tags to keep
only articles carrying every one of them; tick article types to keep only
those. The filters combine, and a query is searched with the tags and types
too. *Neighbours* also shows the nodes linked to the matches (matches have a
yellow ring); *Clear* shows everything again. The graph fits the matches as
you filter. Tags are matched as they are on articles, without the tags under
them in a =taxonomy.org=.

** ⚠️ Ingesting, Distilling and Asking

*Scimax: Ingest File into Crucible* ([[cmd:scimax.crucible.ingest]]) runs
=crucible ingest= on the active file, or on the file you right-click in the
Explorer or on an editor tab. The file goes into the crucible it sits in, or
else the one you pick. For a PDF, Markdown or HTML file it asks for an
optional DOI, so the source gets the full BibTeX entry from doi.org; leave it
empty and crucible looks for a DOI in the text. Unsaved changes are saved
first, since crucible stores a sealed copy of the file as it is on disk:
later edits to the file do not change the source. When it is done, Scimax
shows the cite key, with buttons to copy it or distill the source.

Distilling a source into wiki articles is the LLM's work, so Scimax hands it
to Claude Code (the Claude Code extension must be installed). *Scimax:
Distill Crucible Source with Claude Code* ([[cmd:scimax.crucible.distill]],
also on a crucible's right-click menu in the panel) lists the crucible's
undigested sources (=crucible undigested=). Pick one, optionally type a focus
(for example /the kinetics results/; press Enter for the whole source), and
a new Claude Code chat opens with a prompt naming the crucible, the source
and its cite key. The prompt asks Claude to show you a plan before writing
any article, and to run =crucible sync= and =crucible lint= when it is done.
Review the prompt and send it.

*Scimax: Ask Crucible with Claude Code* ([[cmd:scimax.crucible.ask]], also on
a crucible's right-click menu) asks a question of the knowledge base. Type
the question and a Claude Code chat opens with it, asking Claude to search
the crucible, read the relevant articles, and answer from them with links to
the articles and the cite keys of their sources, saying what the wiki does
not cover. It does not edit the wiki.

** Keeping the Database Current

Crucible's database is updated by =crucible sync=. When you save an article
in a crucible wiki, Scimax runs it in the background once your saves pause,
then refreshes the panel, the bibliography and the lint issues; set
~scimax.crucible.syncOnSave~ to =false= to turn this off. A failed background
sync shows a warning in the status bar (and in the Scimax log), not a pop-up.

*Scimax: Sync Crucible Database* ([[cmd:scimax.crucible.sync]]) runs it for
the current crucible (or the one whose sync button you click). Run it after
an agent or another program edits articles, since only saves in VS Code
trigger the automatic sync.

** Lint Issues in the Problems Panel

Scimax shows =crucible lint= issues in the Problems panel: broken links,
citation keys missing from =references.bib=, articles without
=ARTICLE_TYPE= or file tags, wiki files not yet synced, orphan articles and
undigested sources. Each issue is on the file it concerns, at the broken link
or citation when there is one; issues about the crucible as a whole (a
concept with no article of its own) are on its =index.org=. Errors, warnings
and notes keep crucible's severity.

The issues are checked when you first open an article in a crucible and
after each sync. *Scimax: Lint Crucible* ([[cmd:scimax.crucible.lint]], also
on a crucible's right-click menu in the panel) checks again and opens the
Problems panel. Set ~scimax.crucible.showLint~ to =false= to hide them.

** Settings

| Setting                     | Default    | Description                                 |
|-----------------------------+------------+---------------------------------------------|
| scimax.crucible.command     | "crucible" | The crucible CLI (full path if not on PATH) |
| scimax.crucible.searchMode  | "auto"     | auto, fts, semantic or hybrid               |
| scimax.crucible.searchLimit | 20         | Most search results shown                   |
| scimax.crucible.syncOnSave  | true       | Run crucible sync after saving an article   |
| scimax.crucible.showLint    | true       | Show lint issues in the Problems panel      |
