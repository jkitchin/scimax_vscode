* Overview

Scimax supports [[https://marp.app/][Marp]] slide decks on its own: a Markdown file whose front
matter has ~marp: true~. It renders the slides with its own copy of Marp Core,
so the [[https://marketplace.visualstudio.com/items?itemName=marp-team.marp-vscode][Marp for VS Code]] extension is not needed.

| Task                             | How                                                                                                                     |
|----------------------------------+-------------------------------------------------------------------------------------------------------------------------|
| See one slide as you edit        | Slide preview: the play-preview button in the editor title bar ([[*Slide Preview][Slide Preview]])                      |
| See and rearrange the whole deck | Slide Sorter and the Marp Slides sidebar ([[*Slide Thumbnails][Slide Thumbnails]], [[*Editing Slides][Editing Slides]]) |
| Present                          | =C-c C-e x=, the play button, or a ~marp:~ link in an org file ([[*Slideshow][Slideshow]])                              |
| Write directives                 | Completion and hover in the front matter and comments ([[*Directives][Directives]])                                     |
| Export                           | =C-c C-e= for PDF, PowerPoint, Google Slides, HTML, images ([[*Exporting Slides][Exporting Slides]])                    |

For help, *Scimax: Marp Help* ([[cmd:scimax.marp.help]], also at the bottom of
the Marp menu, as =C-c C-e ?= and as ? in the Marp Slides view) opens this
guide or the online Marp documentation: slide syntax, directives, image
syntax, fragmented lists, theme CSS, the built-in themes and Marp CLI.

To make a Markdown file a deck, run *Scimax: Make Marp Deck*
([[cmd:scimax.marp.insertHeader]]), also in the editor's right-click menu of
a Markdown file that is not a deck yet. It inserts the header below, with the
theme and page numbers as choices (=Tab= moves between them); if the file
already has front matter, it adds ~marp: true~ to it.

A minimal deck:

#+begin_src markdown
---
marp: true
theme: default
paginate: true
---

# Title slide

---

## Second slide

- A point
#+end_src

In a Marp deck, =Cmd+Shift+V= (=Ctrl+Shift+V= on Windows and Linux) opens the
Slide Sorter instead of VS Code's Markdown preview. The Markdown preview is
still there with =Cmd+K V= (beside the editor), and shows a Marp deck as
slides too: Scimax renders it with Marp Core, in
the deck's theme, with scroll sync and double-click to the source (see
[[*Double-Click in the Markdown Preview][Double-Click in the Markdown Preview]]). Other Markdown files preview as usual.

If you also have Marp for VS Code, it and Scimax both render decks in the
Markdown preview; either works. Its ~markdown.marp.*~ settings are used when
the matching ~scimax.marp.*~ ones are not set.

* Double-Click in the Markdown Preview

VS Code's Markdown preview shows a Marp deck as slides (Scimax renders it;
Marp for VS Code is not needed). Double-clicking in it jumps to the exact
source line. The [[*Slide Preview][Slide Preview]] is the alternative that shows one slide
at a time.

1. Open a Marp deck (a Markdown file whose front matter has ~marp: true~).
2. Open the preview: ~Markdown: Open Preview to the Side~ (=Ctrl+K V=, =Cmd+K V= on macOS) or
   ~Markdown: Open Preview~ from the command palette. (In a Marp deck
   =Cmd+Shift+V= opens the Slide Sorter instead.)
3. Double-click the text you want to edit.

The editor comes forward (or opens, if the file was not visible), the cursor
moves to the start of that line, and the line is scrolled into view.

** Where the cursor lands

The line is taken from the element under the pointer, not from its vertical
position on the page, so it stays accurate in scaled slides.

| Double-click on                  | Cursor goes to                                       |
|----------------------------------+------------------------------------------------------|
| A heading                        | The heading line                                     |
| A line of a multi-line paragraph | That source line of the paragraph                    |
| A list item (at any depth)       | That item's line                                     |
| A line of a fenced code block    | That line of code (not the fence)                    |
| A table row                      | That row                                             |
| Empty space on a slide           | The slide's ~---~ separator (file start for slide 1) |

Links are left alone: double-clicking one does not jump to the source.

* Reveal the Cursor in the Preview

This is for VS Code's Markdown preview (of a deck or any Markdown file); the
[[*Slide Preview][Slide Preview]] follows the cursor by itself. The other direction: from the ~.md~ editor, run ~Scimax: Reveal Cursor in
Markdown Preview~ ([[cmd:scimax.marp.revealInPreview]]) from the command palette.
The preview scrolls so that the element on the cursor line sits at its top,
and the editor scrolls the same line to its first visible row. If no preview
is open, one opens to the side first. Focus stays in the editor.

It works for any Markdown preview, Marp or not. It uses the preview's
scroll sync, so ~markdown.preview.scrollPreviewWithEditor~ must be on (the
default).

The command has no default keybinding. To add one, open Keyboard Shortcuts
and search for ~scimax.marp.revealInPreview~.

* Slide Preview

The slide preview shows the slide under the editor cursor, fitted to its
tab, and follows the cursor as you move and type. Open it with the preview
button in a Marp deck's editor title bar, or ~Scimax: Open Marp Slide
Preview~ ([[cmd:scimax.marp.openSlidePreview]]). It opens beside the deck
and leaves the focus in the editor.

The preview is the Slide Sorter tab in /slide/ mode. The two buttons at the
left of its toolbar switch between one slide and the grid of all slides
(=V= does too), and the tab remembers the last mode. The Marp Slides sidebar
view has the same buttons, so it can be a small preview too.

| Key or action                                                     | Effect                                                   |
|-------------------------------------------------------------------+----------------------------------------------------------|
| Move the editor cursor                                            | Shows the slide under it                                 |
| =Left= / =Right=, =Up= / =Down=, =Page Up= / =Page Down=, =Space= | Previous / next slide                                    |
| ‹ and › in the toolbar                                            | Previous / next slide                                    |
| Double-click the slide                                            | Cursor to the slide's first content line                 |
| =V=, or the grid and slide buttons                                | Switch between one slide and the grid                    |
| Right-click                                                       | The slide menu (see [[*Editing Slides][Editing Slides]]) |

Hidden slides are shown (dimmed in the grid) so they can still be edited.

* Slideshow

To present, Scimax makes Marp's HTML slideshow of the deck and opens it in the
browser. Marp CLI builds it (see [[*Marp CLI][Marp CLI]]), and it is written to a private folder
of the extension's storage, one per deck, so nothing is added next to the deck.
Relative images still load from the deck's folder. Unsaved changes are saved
first.

| Command                                                                                   | Starts at                  |
|-------------------------------------------------------------------------------------------+----------------------------|
| ~Scimax: Present Marp Slides~ ([[cmd:scimax.marp.present]])                               | The first slide            |
| ~Scimax: Present Marp Slides from Current Slide~ ([[cmd:scimax.marp.presentFromCurrent]]) | The slide under the cursor |
| Present from This Slide (thumbnail menu)                                                  | The clicked slide          |

The play button in a Marp deck's editor title bar presents from the start,
and so does =x= in the export menu (=C-c C-e=); =c= there starts at the
current slide.

| Key in the slideshow                         | Effect                                                                     |
|----------------------------------------------+----------------------------------------------------------------------------|
| =Right=, =Down=, =Space=, =Page Down=, click | Next slide                                                                 |
| =Left=, =Up=, =Page Up=                      | Previous slide                                                             |
| =F=                                          | Full screen                                                                |
| =P=                                          | Presenter view: current and next slide, notes and a timer, in a new window |
| =Home= / =End=                               | First / last slide                                                         |

The four squares in the slideshow's control bar (bottom left, between full
screen and the presenter view) open Marp's overview: every slide as a
thumbnail. Click one to go there. It needs Marp CLI 4.3 or later; with an older
one the button is missing (=marp --version= shows yours, and
=npm install -g @marp-team/marp-cli@latest= updates it). In a ~presenter: true~
deck each thumbnail shows that slide's ink and sticky notes, and the
slideshow's own ink comes back when you pick a slide.

Hidden slides are left out of the slideshow, and its slide numbers count only
the slides it shows.

A deck with ~presenter: true~ also gets a pen, a laser pointer, sticky notes
and live Python cells in the slideshow; see [[*Presenter Tools and Live Python][Presenter Tools and Live Python]].
Because each deck always uses the same folder, ink drawn in one slideshow is
still there the next time.

** Live reload

While the slideshow is open, saving the deck rebuilds it and the browser
reloads at the slide you are editing (the one under the cursor when you
save), so you can fix a slide and see it in the talk's layout without
presenting again. Ink is kept. Edits are picked up only on save, and only
for a slideshow started from this VS Code window.

The page checks for a new build once a second by loading a small
~<name>.html.version.js~ file written next to it, so it needs no server. Turn it
off with ~scimax.marp.liveReload~.

** Presenting from an org file

A ~marp:~ link in an org file launches the slideshow when clicked (or with
=C-c C-o= on it):

#+begin_example
[[marp:talks/group-meeting.md][Group meeting slides]]
[[marp:talks/group-meeting.md::5][Start at slide 5]]
#+end_example

The path is relative to the org file (absolute paths and ~~/~ work too), and
~::N~ starts at slide /N/. When the org file is exported, the link becomes an
ordinary link to the ~.md~ file.

* Directives

Marp directives set a deck's theme, pagination, headers and so on. Global
directives go in the front matter. Local directives go in the front matter
(for every slide) or in an HTML comment (from that slide on); with a leading
underscore, ~<!-- _class: lead -->~, they apply to that one slide.

In a Marp deck, Scimax completes directive names as you type them at the
start of a front matter line or inside ~<!-- -->~, then their values, and
shows what a directive does when you hover over it.

| Directive                                                                     | Scope  | Values offered                                                      |
|-------------------------------------------------------------------------------+--------+---------------------------------------------------------------------|
| ~theme~                                                                       | Global | ~default~, ~gaia~, ~uncover~, and themes from ~scimax.marp.themes~  |
| ~paginate~                                                                    | Local  | ~true~, ~false~, ~hold~, ~skip~                                     |
| ~headingDivider~                                                              | Global | ~1~ to ~6~                                                          |
| ~size~                                                                        | Global | ~16:9~, ~4:3~                                                       |
| ~math~                                                                        | Global | ~mathjax~, ~katex~                                                  |
| ~class~                                                                       | Local  | ~lead~, ~invert~                                                    |
| ~transition~                                                                  | Local  | The HTML slideshow transitions (~fade~, ~push~, ...)                |
| ~header~, ~footer~, ~color~, ~background*~                                    | Local  | (free text; ~background*~ positions, repeats and sizes are offered) |
| ~style~, ~lang~, ~title~, ~author~, ~description~, ~keywords~, ~url~, ~image~ | Global | (free text)                                                         |

* Slide Thumbnails

Scimax shows a thumbnail of every slide in the active deck in two places:

- The *Marp Slides* view in the Explorer sidebar. It appears whenever a
  Markdown file with ~marp: true~ in its front matter is the active editor.
  It is often collapsed at the bottom of the Explorer; drag its header to the
  Secondary Side Bar or the bottom panel for more room.
- The *Slide Sorter*, an editor tab that lays the thumbnails out in a grid,
  like a slide sorter in PowerPoint or Keynote. Open it with =Cmd+Shift+V=
  (=Ctrl+Shift+V=) in the deck, ~Scimax: Open Marp Slide Sorter~
  ([[cmd:scimax.marp.openSlideSorter]]), or the layout
  button in the deck's editor title bar or the sidebar view's title bar. It
  opens beside the deck, and like any tab it can be split, moved or dragged
  into its own window. It reopens after a reload.

Both follow the active Marp deck and keep showing it while you work in its
preview or in the sorter. Both do everything described here and in
[[*Editing Slides][Editing Slides]]; the sorter just has more room.

Double-click a thumbnail to jump to the text that defines that slide. The
editor comes forward with the cursor on the slide's first content line and
that line scrolled to the top. The slide's ~---~ separator, the front matter
(for slide 1), blank lines and directive comments such as
~<!-- _class: lead -->~ are skipped. A slide with no content puts the cursor
on its separator. From the sorter, a deck that is not open in any group opens
beside the sorter rather than replacing it.

| In the thumbnails               | Effect                                                    |
|---------------------------------+-----------------------------------------------------------|
| Double-click a thumbnail        | Cursor to that slide's first content line                 |
| Click a thumbnail               | Selects it                                                |
| Drag a thumbnail                | Moves the slide (see [[*Editing Slides][Editing Slides]]) |
| Move the cursor in the editor   | Bold number on the slide under the cursor                 |
| Right-click a thumbnail         | Slide menu (see [[*Editing Slides][Editing Slides]])      |
| Zoom slider, or =+= / =-= / =0= | Larger, smaller or default thumbnails                     |
| Pinch, or =Ctrl= + scroll       | Zoom                                                      |
| Refresh button                  | Re-renders the deck                                       |

** Zoom

The slider in the toolbar at the top sets the thumbnail width, from 80 to 640
pixels. The thumbnails flow into as many columns as fit, so in the sidebar a
small zoom gives two or more columns. By default the sidebar fills its width
with one column and the sorter starts at 240 pixels. Each remembers its own
zoom. The keys =+= and =-= step the zoom and =0= resets it; they are plain keys
because =Cmd+==/=Cmd+-= zoom the whole VS Code window. A trackpad pinch (or
=Ctrl= + scroll wheel) zooms too.

The thumbnails re-render as you type (after a short pause). Slide boundaries
come from Marp itself, so ~---~, ~***~ and ~___~ separators and the
~headingDivider~ directive all split slides exactly as they do in the preview,
and a ~---~ inside a code block does not.

The view renders with its own copy of Marp Core and follows these settings
(see [[*Configuration][Configuration]]):

| Setting                       | Effect on thumbnails                                         |
|-------------------------------+--------------------------------------------------------------|
| ~scimax.marp.themes~          | Custom theme CSS files (local paths only; URLs are skipped)  |
| ~scimax.marp.enableHtml~      | Allows all raw HTML; otherwise Marp's safe allowlist applies |
| ~scimax.marp.mathTypesetting~ | ~mathjax~ (default), ~katex~ or ~off~                        |

Run ~Scimax: Refresh Marp Slide Thumbnails~ ([[cmd:scimax.marp.refreshSlides]])
after editing a theme file, since theme files are not watched.

* Editing Slides

The Marp Slides view and the Slide Sorter can rearrange a deck without
scrolling through the Markdown. Each change edits the ~.md~ file directly and is a single edit, so
one Undo in the editor (or =Cmd+Z= in the view) reverses it. Only the lines
that change are rewritten; the rest of the file is left exactly as it was.

** Selecting slides

Click a thumbnail to select it, =Cmd+click= (=Ctrl+click= on Windows and
Linux) to add or remove one, and =Shift+click= to select a range. =Left= and
=Right= move the selection by one slide and =Up= and =Down= by one row of the
grid (=Shift= extends it), =Home= and =End= jump to the first and last slide,
and =Cmd+A= selects them all. Right-clicking a slide that is not selected
selects just that slide, as in the Explorer.

** Drag and drop

Drag a thumbnail to move its slide. A bar shows where it will land: between
two thumbnails in the grid, or between two rows in a single column. Dragging
a selected thumbnail moves the whole selection, in order, as one block, even
when the selected slides were not next to each other. Dropping past the last
thumbnail moves the slides to the end.

** How the Markdown changes

Copy and Cut put the slides' Markdown on the system clipboard, joined with
~---~, so you can also paste them into another deck or any file. Paste reads
Markdown from the clipboard: text copied from the view comes back as the same
slides, and any other text becomes one new slide.

** Pasting slides with images

Slides often show images by relative path, such as ~![bg](figs/a.png)~, which
would break in a deck in another folder. So Copy and Cut write every relative
path in the slides as an absolute one, and Paste makes them relative to the
deck you paste into. Pasting back into the same deck gives the original
paths. This covers Markdown images and links, ~<img>~, ~<video>~ and other
HTML ~src~ attributes, and ~url(...)~ in directives such as
~<!-- _backgroundImage: url(bg.png) -->~ and in ~<style scoped>~ blocks. Code
and URLs are left alone.

When you paste into a deck in another folder and some images are outside that
deck's folder, Paste asks what to do:

- *Copy the images into this deck's folder*: an image under the source deck's
  folder keeps its path relative to the deck (~figs/a.png~ goes to
  ~figs/a.png~ beside the new deck); any other image goes into ~figs/~. A file
  already there with the same content is reused; a different file with the
  same name gets a numbered name (~a-1.png~).
- *Link to the original images*: the paths point back at the originals.
- *Cancel paste*.

Cut never moves or deletes images. Slides pasted with an ordinary Cmd+V in the
editor keep the absolute paths, which work on your computer but not on
someone else's.

Slide 1 never takes the front matter with it. Moving, pasting or deleting
slides adds or drops ~---~ separators as needed, so the first slide never
starts with one and slides never merge. In a deck using ~headingDivider~, a
slide that starts with a divider-level heading gets no separator, since the
heading already starts a slide. A slide's own directive comments
(~<!-- _class: lead -->~) and speaker notes move with it.

Insert New Slide adds an empty slide (a ~---~ line and a blank line) and moves
the cursor into it, ready to type.

** Hidden slides

Marp has no way to skip a slide, so Hide Slide wraps it in a comment that
Scimax recognizes:

#+begin_example
<!-- scimax-hidden
# Backup results
Details for questions.
scimax-hidden -->
#+end_example

Marp does not render the comment, so the slide is left out of the preview and
of every export. Its thumbnail stays in the view, dimmed and marked /hidden/,
and can be moved, copied or unhidden like any other slide. Any ~-->~ inside
the hidden slide (such as its own directive comments) is written as ~-\->~
so it cannot end the comment early, and Unhide restores it.

One side effect: Marp treats comments as presenter notes, so the hidden
slide's text appears in the notes of the slide before it (for example in the
presenter view of an HTML export).

** Custom themes

/New Custom Theme.../ asks for a name and a built-in theme to start from, then:

1. writes ~themes/<name>.css~ in the workspace folder (next to the deck
   outside a workspace), with ~/* @theme <name> */~, ~@import '<base>';~ and
   commented-out rules for the usual things to change;

4. opens the CSS beside the deck.

* Editing Slides with Claude Code

With the [[https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code][Claude Code]] extension installed, right-click a thumbnail (or several
selected ones) and choose *Edit with Claude Code…*. Claude Code opens with a
prompt already filled in that names the deck, the slides and their lines,
and ends with "Change: ", for example:

#+begin_example
In the Marp slide deck talks/deck.md, edit slide 3 (lines 25-38). Change
only that slide and keep the rest of the deck as it is. Change:
#+end_example

Type what you want ("split this into two columns with the figure on the
right") and send it. Claude Code reads the deck and edits it with its own
tools, showing you the changes, and you can keep the conversation going. The
thumbnails and preview update as the file changes.

In the ~.md~ file, *Scimax: Edit Marp Slide with Claude Code*
([[cmd:scimax.marp.editSlideWithClaude]], also in the editor's right-click menu)
does the same for the slide under the cursor, or every slide the selection
touches. Unsaved changes are saved first, since Claude Code reads the file.

Claude Code has no command that takes a prompt from another extension, so
this uses its ~vscode://anthropic.claude-code/open?prompt=~ link: the prompt
is filled in but not sent, and it opens in a new Claude Code tab.

If a Claude Code tab is already open, the slides go to that chat instead:
their lines are selected in the deck and added to the chat's input as an
@-mention (for example ~@talks/deck.md#L25-38~), and you type the change
after it. Claude Code's link can only fill in a prompt in a new tab, which is
why an open chat gets the @-mention rather than the full sentence. A chat open
only in the Claude Code side bar is not detected, so a new tab opens.

** Talk timer

Give the length of the talk with a ~timer~ key and a small countdown sits in
the top-right corner of every slide:

#+begin_src markdown
---
marp: true
presenter: true
timer: 20
---
#+end_src

A bare number is minutes; ~20m~, ~45:00~, ~1h30m~ and ~90s~ also work. Deck →
Talk Timer... in the Marp menu ([[cmd:scimax.marp.deck.timer]]) sets it, and
turns on the presenter tools if the deck does not have them (the timer is one
of them).

- It starts by itself the first time you move off the slide the show opened
  on. =t= (or a click on the timer) starts and pauses it; =T= resets it to
  the full time.
- It turns amber in the last 5 minutes (the last fifth of a short talk), red
  in the last minute, and after time is up counts the overtime as =-1:05=.
- The audience window and Marp's presenter view (=P=), where the countdown
  sits next to Marp's clock, show the same time: pausing in one pauses both.
  The time is kept in the browser's local storage, so a reload, or a live
  reload when you save the deck, does not reset it.
- After a rehearsal, press =T= before the talk. A timer untouched for 12
  hours, or a deck rebuilt with a different ~timer~, starts afresh.
- It is not printed and is not in PDF, PowerPoint or image exports.

** Exercise countdowns

A ~countdown~ fence puts a countdown box on a slide, for an exercise or a
discussion. The first line is the time, the rest is the label (Markdown):

#+begin_src markdown
```countdown 3:00
Discuss with your neighbour: *which step is rate limiting?*
```
#+end_src

The time is written as for the talk timer: a bare number is minutes, and
~3:00~, ~90s~ and ~2m30s~ also work (the default is 5 minutes). Insert →
Exercise Countdown... in the Marp menu ([[cmd:scimax.marp.insert.countdown]])
adds one and turns on the presenter tools.

- =e= (or a click on the box) starts and pauses the countdown on the current
  slide; =E= resets it.
- At zero it flashes red and reads "Time's up".
- It runs in step in the audience window and the presenter view, and is kept
  across a reload.
- The Markdown preview and the slide thumbnails show the box; PDF and
  PowerPoint exports show it with its full time.

** Blank, zoom and go to a slide

- *Blank screen.* =b= turns the audience screen black and =w= white, so the
  room looks at you instead of the slide. Press the key again, =Esc=, or
  click to bring the slide back. Pressed in Marp's presenter view, it blanks
  the audience window and the presenter view shows a reminder instead of
  going blank itself.
- *Zoom.* =x= then drag a box over a dense figure or table to magnify that
  part to fill the screen (a click magnifies 2.5 times around that point).
  The audience window zooms too. =x= or =Esc= zooms out, as does moving to
  another slide. The pen still works while zoomed and the ink stays on the
  slide.
- *Go to a slide.* =g= opens a list of slides by number and title. Type a
  number or words from a slide's title or text, use the arrows, and press
  Enter. Without the list, type a slide number and press Enter: =1= =2=
  Enter goes to slide 12.

** Editing slides in the slideshow

For last-minute polish just before a talk, =d= lets you fix the slides in
the slideshow itself: correct a typo, move a heading, make a figure bigger,
or hide a line. A bar at the top says what is selected and what you can do.
The edits stay in the HTML; they do not change the Markdown.

| Key or action      | Effect                                                                      |
|--------------------+-----------------------------------------------------------------------------|
| =d=                | Start or stop editing (also in the right-click menu)                        |
| Double-click slide | Start editing there: type in the text, or select an image, table, ...       |
| Click              | Select a heading, paragraph, list item, image, table, code or widget        |
| Drag               | Move it (hold Shift to keep it level or upright)                            |
| Double-click       | Edit its text; Enter or a click elsewhere finishes, Shift+Enter breaks line |
| Enter              | Edit the selected text                                                      |
| Arrows             | Nudge the selection (Shift: 10 px); with nothing selected, change slide     |
| =+= / =-=          | Bigger / smaller: text size, or the width of an image, table or code        |
| Corner handle      | Drag to resize                                                              |
| Delete             | Hide it (it shows faintly while editing); Delete again shows it             |
| Tab / Shift+Tab    | Select the enclosing block (the list, not the item) / back again            |
| =0=                | Undo every edit to the selection                                            |
| =Cmd+Z= / =Ctrl+Z= | Undo (add Shift, or use =Cmd+Y=, to redo); the bar has Undo and Reset slide |
| =Esc=              | Clear the selection, then stop editing                                      |

- Edits are kept in the browser's local storage, so a reload keeps them,
  and Marp's presenter view shows them as you make them. You edit in the
  audience window, not the presenter view.
- =s= saves the deck with its edits, ink and notes in one file, and opening
  that file brings the edits back. The JSON save (=S=) and load (=i=)
  include them too. =m= cannot put them in Markdown, and says so.
- Edits belong to the content of their slide. If you change a slide in the
  Markdown and the slideshow reloads, that slide's edits are set aside
  rather than put in the wrong place, and a message says so. Slides you did
  not change keep theirs, even if they moved.
- Text you type or paste is plain text; maths in a paragraph stays as it
  is. Code cells, countdowns and widgets can be moved and resized but not
  typed in.
- Printing (=Cmd+P=) shows the slides as edited.

To keep a change for good, make it in the Markdown too.

** Keeping the ink

Ink and notes belong to the slide they were drawn on and are kept in the
browser's local storage, so a reload does not lose them. Scimax presents a
deck with presenter tools from the same private folder every time, so the ink
is still there when you present it again. To keep the ink for good, move it to
another machine or share it, press =s=: the browser downloads one HTML file
with the theme, images, iframes, fonts, tools and ink inside. Open it
anywhere, keep annotating, and press =s= again.

** Live Python cells

Mark a Python code block with ~run~ to make it a cell you can edit and run
during the talk:

#+begin_src markdown
```python run
import numpy as np
np.linspace(0, 1, 5)
```
#+end_src

| Fence                  | Cell                                              |
|------------------------+---------------------------------------------------|
| ~```python run~        | Editable, with a Run button                       |
| ~```python run auto~   | Runs by itself the first time its slide is shown  |
| ~```python run hidden~ | Setup code: not shown, runs before the first cell |

Insert one with Insert → Python Cell... ([[cmd:scimax.marp.insert.pythonCell]]),
which also adds ~presenter: true~ if the deck does not have it.

In the slideshow, click a cell to edit it, press =Shift+Enter= (or =▶=) to run
it and =Esc= to leave the editor so the arrow keys change slides again. =↺=
restores the original code and =⟲= restarts Python. All cells share one
Python session, like a notebook. Output shows printed text, errors, the value
of the last expression and matplotlib figures.

Python is [[https://pyodide.org][Pyodide]], running in the browser. With ~presenter: true~ it is
downloaded from the jsdelivr CDN when the deck opens, so *running cells needs
an internet connection* (the rest of the tools work offline). To present
without one, use ~presenter: offline~ (see [[*Offline Python][Offline Python]]). Pyodide's packages
(numpy, scipy, matplotlib, pandas, sympy, ...) load on ~import~, and ~%pip
install name~ in a cell installs pure-Python packages from PyPI. An ~import~
that fails is retried once by installing the package from PyPI (~import
pycse~ installs pycse). Python starts downloading in the background when the
deck opens, along with the packages the cells import.

In PDF, PowerPoint and image exports a ~run~ cell is ordinary highlighted code,
and a ~run hidden~ cell is left out.

** Running cells in VS Code

Press =C-c C-c= in a ~run~ cell to run it while you write the deck, without
presenting. The output shows in a /Python/ panel beside the editor, from the
same Pyodide the slideshow uses, so code that works there works in the talk.

| Command                                                               | Key       | Effect                                              |
|-----------------------------------------------------------------------+-----------+-----------------------------------------------------|
| ~Scimax Marp: Run Python Cell~ ([[cmd:scimax.marp.runCell]])          | =C-c C-c= | Run the cell under the cursor                       |
| ~Scimax Marp: Run All Python Cells~ ([[cmd:scimax.marp.runAllCells]]) |           | Restart Python and run every shown cell in order    |
| ~Scimax Marp: Restart Python~ ([[cmd:scimax.marp.restartPython]])     |           | A fresh Python: variables and imports are forgotten |

- All cells of the deck share one Python, as in the slideshow. The ~run hidden~
  cells run first, once, before the first cell you run.
- Each output is labelled with its slide and cell number; click the label to
  go to the cell. *Clear* removes the output and *Restart* restarts Python.
- The panel is for one deck at a time: running a cell of another deck
  restarts Python for that deck.
- A ~presenter: offline~ deck runs from the Python files it carries, so this
  works without a connection too; otherwise Pyodide is downloaded when the
  first cell runs.
- Cells run only in a trusted workspace. The cells are also in Insert →
  Python Cell... and the commands are in the Marp menu's Insert section.
- =C-c C-c= elsewhere in a Markdown file keeps its usual meaning (run a Babel
  code block, toggle a checkbox).

** Offline Python

Set ~presenter: offline~ instead of ~presenter: true~ (or choose "On, with
offline Python" in Deck → Presenter Tools...) to put Python inside the deck,
so its cells run with no internet connection:

#+begin_src markdown
---
marp: true
presenter: offline
---
#+end_src

- When you present or export HTML (=h=), Scimax adds Pyodide and the packages
  the deck's ~run~ cells import (with their dependencies) to the HTML file.
  Pyodide is downloaded once per version and cached in the extension's
  storage, so later builds need no connection either.
- Packages are found from the top-level ~import~ / ~from ... import~ lines
  of the ~run~ cells. To include a package that is only imported later, during
  the talk, import it in a ~run hidden~ cell.
- The file grows by about 12 MB for Python alone, and to 35-45 MB with numpy,
  matplotlib and pandas. It loads in a few seconds from disk.
- ~%pip install~, and packages that are not part of Pyodide (for example
  ~pycse~ or ~seaborn~), still need a connection; the deck tries to download
  them, and the cell shows an error when it cannot. The Output panel (/Scimax
  Marp Export/) lists the packages that were included and those that were not.
- =s= keeps the embedded Python, so the annotated copy also runs offline.
- In the slideshow of a ~presenter: true~ deck, right-click → /Save a copy that
  works offline.../ saves ~<deck>-offline.html~. That copy contains Python, the
  packages chosen as above (including any edits you made to the cells), and
  your ink, notes and edits. The browser downloads Python for it, so you need
  a connection while saving, but not afterwards. When you save that copy again
  with =s=, it keeps the ~-offline~ name.

** Checking a deck for offline use

~Scimax Marp: Check for Offline Use~ ([[cmd:scimax.marp.checkOffline]], also Deck →
Check for Offline Use in the Marp menu) builds the deck in a temporary folder
and lists in the Problems panel what would not work without an internet
connection, each on the line it comes from:

- Python cells in a deck with ~presenter: true~ (Python is downloaded when the
  deck opens; use ~presenter: offline~)
- ~%pip~ lines, and imports of packages that are not part of Pyodide, in an
  offline deck
- images and other files that are not found
- images, videos and scripts loaded from the web, and fonts or styles a theme
  loads from the web (shown on the ~theme:~ line)

Presenting or exporting HTML (=h=) an offline deck runs the same check and
says when it found something. The problems are cleared when the deck is
closed or checked again.

** Notes

- The tools are added only in a trusted workspace, since the deck's HTML and
  Python run in the browser. In an untrusted workspace Scimax warns and shows
  the plain slideshow.
- A deck with ~presenter: true~ is built with Marp CLI's ~--html~ option, so raw
  HTML in its slides is rendered. The slide thumbnails and previews allow all
  HTML for these decks too (in a trusted workspace), so an ~<iframe>~ widget
  shows there as well, whatever ~scimax.marp.enableHtml~ says.
- Scimax passes its own markdown-it engine to Marp CLI (~--engine~), which
  replaces an ~engine~ set in a Marp CLI configuration file for these decks.
- The fonts for KaTeX math are downloaded once and cached, so ~deck.html~ also
  typesets math offline. Fonts that a theme loads from the web (an ~@import~
  of a font service) fall back to local fonts without a connection.
- The browser files live in ~media/marpPresent/~ of the extension; the Output
  panel (/Scimax Marp Export/) lists what was inlined and any missing files.

** Marp CLI

All exports except =d= run [[https://github.com/marp-team/marp-cli][Marp CLI]], the tool behind Marp for VS Code's own
export. Scimax uses ~scimax.marp.cliPath~ if set, then ~marp~ on the PATH
(=npm install -g @marp-team/marp-cli=). Failing both, it offers to run it with
~npx~, which downloads Marp CLI the first time. It asks once and remembers the
answer.

PDF, PowerPoint and image exports render the slides in Google Chrome,
Microsoft Edge or Firefox, so one of them must be installed. Local images are
included when the workspace is trusted (see ~scimax.marp.allowLocalFiles~).
The export follows ~scimax.marp.themes~ and ~scimax.marp.enableHtml~, so it
matches the thumbnails. Marp CLI's output is in the /Scimax Marp Export/ output
channel.

** Which PowerPoint

There are three PowerPoint exports:

|                        | PowerPoint (=s=) | Editable, Marp (=e=)    | Editable, Pandoc (=d=)                  |
|------------------------+------------------+-------------------------+-----------------------------------------|
| Looks like the preview | Exactly          | Mostly                  | No: PowerPoint default or your template |
| Text editable          | No (pictures)    | Yes                     | Yes                                     |
| Presenter notes        | Yes              | No                      | Yes                                     |
| Needs                  | Browser          | Browser and LibreOffice | Pandoc                                  |

Marp's editable PowerPoint is experimental: complex themes (such as ~gaia~)
may fail or come out incomplete. If LibreOffice is missing, the error offers
the Pandoc export or the picture PowerPoint instead.

The Pandoc export gives real text boxes and notes in PowerPoint's own layouts.
Set ~scimax.marp.pandocReferenceDoc~ to a ~.pptx~ to use its layouts and
styles instead. Scimax prepares the deck for Pandoc: every Marp slide
(including those made by ~headingDivider~) becomes one slide, presenter-note
comments become speaker notes, directive comments and hidden slides are
dropped, and Marp image keywords (~bg~, ~w:300~, ...) are removed. A slide
with both text and pictures gets two columns, with the pictures on the right
(on the left for ~bg left~), since Pandoc would otherwise move the text to a
slide of its own. A ~title:~ in the front matter makes a title slide.

** Google Slides

Google Slides has no import from Marp, but it opens PowerPoint files, and
editable ones import best. The =g= export makes Marp's editable PowerPoint
when LibreOffice is installed, otherwise the Pandoc one, otherwise (after
asking) the picture PowerPoint. The notification links to Google Drive:
upload the file (New > File upload), then open it with Google Slides.

** Marp CLI configuration files

A deck set up for Marp CLI often keeps its themes and options in a
configuration file beside it rather than in VS Code settings:

#+begin_src yaml
# .marprc.yml
themeSet: ./theme
html: true
#+end_src

Scimax reads the same file, so the thumbnails, the slide preview, the
Markdown preview and exports show the deck the way Marp CLI renders it. It
uses the nearest ~.marprc~, ~.marprc.json~, ~.marprc.yaml~, ~.marprc.yml~ or
~marp~ key of ~package.json~, looking in the deck's folder and then each folder
above it up to the workspace folder. Paths in the file are relative to it.

| Key            | Effect in Scimax                                                                    |
|----------------+-------------------------------------------------------------------------------------|
| ~themeSet~     | Theme CSS files or folders (all ~.css~ files inside), added to ~scimax.marp.themes~ |
| ~html~         | ~true~ or ~false~, used when ~scimax.marp.enableHtml~ is not set                    |
| ~options.math~ | ~katex~, ~mathjax~ or ~false~, used when ~scimax.marp.mathTypesetting~ is not set   |

An ~html~ allowlist object is not supported, and JavaScript configuration
files (~marp.config.js~, ~.marprc.js~) are not run. Saving the configuration
file updates the thumbnails. The Marp for VS Code extension does not read
these files, so if it is installed and renders the Markdown preview, set
~markdown.marp.themes~ for it as well.

** Double-click in the Markdown preview

Double-click in the Markdown preview follows VS
Code's own setting for double-clicking in the Markdown
preview. Current VS Code releases turn it off by default, so enable it once in
your user settings:

#+begin_src json
"markdown.preview.doubleClickToSwitchToEditor": true
#+end_src

| Setting                                        | Default | Effect                                      |
|------------------------------------------------+---------+---------------------------------------------|
| ~markdown.preview.doubleClickToSwitchToEditor~ | ~false~ | Set to ~true~ to turn on double-click jumps |

If double-clicking a slide does nothing, this setting is the first thing to
check. It also turns on VS Code's own (approximate) double-click for ordinary
Markdown previews.

* How It Works

** Slides in the Markdown preview

Scimax contributes a markdown-it plugin (~markdown.markdownItPlugins~,
~src/marp/marpPreviewPlugin.ts~). For a file with ~marp: true~ in its front
matter it parses and renders with Marp Core instead of plain markdown-it, adds
VS Code's ~code-line~ class and ~data-line~ source line to each block (for
scroll sync and double-click), and puts the deck's theme CSS in front. The
preview script ~media/marp/marpPreviewMode.js~ then turns off VS Code's own
Markdown styles for that preview, since they would leak into the slides, and
~media/marp/marpPreviewSlides.css~ lays the slides out. Marp Core's browser
script (also a preview script) fits headings marked ~<!-- fit -->~.

** Double-click in the Markdown preview

Scimax contributes a preview script (~media/marp/marpPreview.js~) through the
~markdown.previewScripts~ contribution point. Marp already tags each rendered
element with its source line (~data-line~). On double-click inside a slide the
script:

1. finds the nearest element carrying a line number;
2. adds the number of source line breaks between the start of that element and
   the caret (and one for the opening fence of a code block);
3. sends the preview's own ~didClick~ message with that line, so VS Code
   reveals it exactly as it does for its built-in double-click.

VS Code's built-in handler estimates the line by interpolating the click's
vertical position between tagged elements, which drifts inside scaled slides.
Scimax's handler replaces it for Marp slides only; ordinary Markdown previews
are unchanged. If the preview's message channel cannot be reached, the
built-in handler runs as before.
