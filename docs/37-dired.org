* Dired - Directory Editor

Dired (Directory Editor) provides Emacs-style file management in VS Code. It displays directory listings in a webview panel where you can navigate, mark files, and perform bulk operations using familiar Emacs keybindings.

** Opening Dired

| Keybinding | Command                        | Description                                          |
|------------+--------------------------------+------------------------------------------------------|
| ~C-x d~    | =scimax.dired.open=            | Open dired (prompts for directory or uses workspace) |
| ~C-x 5 d~  | =scimax.dired.openOtherWindow= | Open dired in a new window (prompts for directory)   |
|            | =scimax.dired.openCurrent=     | Open dired for current file's directory              |
|            | =scimax.dired.openWorkspace=   | Open dired for workspace root                        |

** Navigation

Once in the dired panel, use these keys to navigate:

| Key                  | Action                       |
|----------------------+------------------------------|
| ~n~ or ~j~ or ~Down~ | Move to next file            |
| ~p~ or ~k~ or ~Up~   | Move to previous file        |
| ~RET~ or ~o~         | Open file/directory          |
| ~^~                  | Navigate to parent directory |
| ~g~                  | Refresh directory listing    |
| ~<~                  | Go to first entry            |
| ~>~                  | Go to last entry             |

** Marking Files

Mark files for batch operations:

| Key   | Action                              |
|-------+-------------------------------------|
| ~m~   | Mark current file and move down     |
| ~u~   | Unmark current file and move down   |
| ~U~   | Unmark all files                    |
| ~t~   | Toggle all marks                    |
| ~d~   | Flag file for deletion              |
| ~% m~ | Mark files matching regex pattern   |
| ~* e~ | Mark edited files (git)             |
| ~* ?~ | Mark untracked files (git)          |
| ~* c~ | Mark files in conflict (git)        |
| ~M~   | Mark files in this file's git state |

Marked files appear with ~*~ indicator. Flagged files (for deletion) appear with ~D~ indicator.

** File Operations

Operate on marked files (or current file if none marked):

| Key | Action                                                  |
|-----+---------------------------------------------------------|
| ~D~ | Delete marked/flagged files (moves to trash by default) |
| ~C~ | Copy marked files (prompts for destination)             |
| ~R~ | Rename/move marked files (prompts for destination)      |
| ~+~ | Create new directory                                    |
| ~f~ | Find a file by name, creating it if it does not exist   |
| ~F~ | Open the current directory in Finder/Explorer           |

~f~ opens the named file, creating it (and missing folders, for a name like
=notes/today.org=) when it does not exist. A new file appears in the listing
with point on it, except in wdired mode, where the listing waits for the
pending renames.

~D~ asks to save open files with unsaved changes inside what it deletes, then
closes their editor tabs. ~F12 f R~ and ~F12 f D~ in dired are the same as ~R~
and ~D~.

With one file, ~R~ asks for a new name relative to the file's folder, so
=archive/notes.org= or =../notes.org= also moves it (missing folders are
created) and point follows the file. In vc-dir the name is the file's own
name, not its path from the repository root.

** Git Status and Version Control

Inside a git repository, dired shows a git status column: =edited=,
=edited, staged=, =edited, part staged=, =added, staged=, =removed=,
=renamed, staged=, =untracked=, =ignored= or =conflict=. Up-to-date files show
nothing. A directory shows the strongest state of the files below it
(conflict, then edited, then untracked), so you can see where the changes are.
Turn the column off with =scimax.dired.showGitStatus=.

The ~C-x v~ commands act on the marked files, or on the file at point when
nothing is marked:

| Key       | Action                                                                     |
|-----------+----------------------------------------------------------------------------|
| ~C-x v v~ | Next action on the whole set (register, commit, resolve), see below        |
| ~C-x v =~ | One multi-file diff of all their changes against HEAD                      |
| ~C-x v l~ | Commits touching any of them; the picked commit opens as a multi-file diff |
| ~C-x v u~ | Discard all their changes, after one confirmation                          |
| ~C-x v i~ | Add a =.gitignore= pattern for each (directories get a trailing =/=)       |
| ~C-x v g~ | Blame the first file                                                       |

=C-x v v= on several files works like Emacs =vc-next-action= on a fileset:
every changed file must be in the same state. Untracked files are registered,
edited files are committed in one commit (=git commit -- files=, so other
staged files stay staged), conflicted files are marked resolved. With files
in different states, it names the files in each state; mark one group with
~* e~, ~* ?~ or ~* c~ and try again. Up-to-date files in the set are left out.

The listing refreshes after each command and keeps your marks. ~M-o~ also
offers these commands, plus Stage / Unstage. To see every changed file in the
repository in one list, use ~C-x v d~ (see [[file:47-version-control.org][Version Control]]).

** Actions Menu (M-o or right-click)

Press ~M-o~ (Option+O on Mac), or right-click a row, to open a fuzzy picker of
actions for that file. On ~.~ or ~..~ the menu offers only the directory action.

| Action                                 | Description                                 |
|----------------------------------------+---------------------------------------------|
| Enter Directory                        | Enter the selected directory                |
| Open in Editor                         | Open file in VS Code editor                 |
| Open in Finder/Explorer                | Reveal in system file manager               |
| Copy Path                              | Copy full path to clipboard                 |
| Copy File                              | Copy file to destination                    |
| Rename/Move                            | Rename or move file                         |
| Delete                                 | Delete file (with confirmation)             |
| Mark                                   | Mark file for batch operations              |
| Unmark                                 | Remove mark from file                       |
| Flag for Deletion                      | Flag file for deletion                      |
| Open This Directory in Finder/Explorer | Open the current directory in the OS        |
| VC: Next Action, Diff, Log, ...        | Git commands on the marks (in a repository) |

** WDired Mode (Writable Dired)

WDired mode allows you to rename files by editing their names directly, like editing text:

| Key       | Action                                    |
|-----------+-------------------------------------------|
| ~C-x C-q~ | Enter wdired mode (names become editable) |
| ~C-c C-c~ | Commit renames                            |
| ~C-c C-k~ | Cancel and exit wdired mode               |

In wdired mode:
1. Edit filenames directly in the listing
2. Changes are highlighted
3. Press ~C-c C-c~ to apply all renames at once
4. Press ~C-c C-k~ to discard changes

A ~C-x v~ command or a File menu rename while you are editing names does not
reload the listing (that would lose your edits); it reloads when wdired ends.

** Sorting and Filtering

| Key | Action                                         |
|-----+------------------------------------------------|
| ~s~ | Cycle sort field (name, size, date, extension) |
| ~.~ | Toggle showing hidden files (dotfiles)         |
| ~/~ | Set filter pattern (regex)                     |

Sorting keeps the marks and the entry at point.

** Display Format

Each line shows:
#+begin_example
drwxr-xr-x  4096  2024-01-15 10:30  Documents/
-rw-r--r--  1234  2024-01-14 09:15  file.txt
lrwxrwxrwx    12  2024-01-13 08:00  link -> target
#+end_example

- First column: file permissions (d=directory, l=symlink, -=file)
- Second column: file size
- Third column: modification date/time
- Fourth column: git status (only inside a git repository)
- Last column: filename (directories end with /)

** Configuration

| Setting                      | Default  | Description                                       |
|------------------------------+----------+---------------------------------------------------|
| ~scimax.dired.showGitStatus~ | ~true~   | Show the git status column in a repository        |
| ~scimax.dired.showHidden~    | ~false~  | Show hidden files by default                      |
| ~scimax.dired.confirmDelete~ | ~true~   | Show confirmation before deleting                 |
| ~scimax.dired.defaultSort~   | ~"name"~ | Default sort field (name, size, mtime, extension) |

** Security

Dired includes security protections:
- Path traversal prevention (no ~..~ in filenames)
- Filename validation (no path separators in names)
- Delete operations use system trash by default
- Regex patterns are validated to prevent ReDoS attacks
